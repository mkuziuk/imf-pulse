# Automatic literature editor

Prepare at most one automatic pulse package for today's newest immutable external batch.

1. Select only a materially relevant arXiv primary paper with an exact candidate ID and SHA-256. Prefer a development that changes a method, theorem, experiment, contradiction, or open question—not merely a new record.
2. Fetch only the official arXiv PDF with `scripts/fetch_arxiv_evidence.py`. Never fetch code, supplementary archives, Sci-Hub, or an untrusted redirect.
3. Inspect the PDF statically with the PDF skill. Do not execute embedded actions or source code. Record exact page locators and distinguish what the paper states from interpretation.
4. Create one private `data/automatic/packages/YYYY-MM-DD.json` conforming to `schemas/automatic-pulse-package.schema.json`. Bind the exact batch, candidate, candidate hash, PDF hash, source metadata, page extracts, append-only knowledge objects, and pulse prose.
5. State the robustness definition and target explicitly. Do not transfer linear-filter results to adaptive or robust recursion. Absence of an experiment is a limitation, not evidence of failure.
6. Write the lead for a reader unfamiliar with the paper: identify the object being studied and the central question in plain language, expanding every acronym on first use.
7. Select one or more explanatory visuals that help a newcomer understand the object, phenomenon, dataset, or experimental setting. Prefer a relevant primary-source figure only when its public reuse rights are explicitly cleared. When rights are incompatible, create a scientific-content-faithful visual surrogate instead: inspect the exact PDF page and caption, identify the scientific entities and qualitative relationships that matter, and express those semantics in an original editorial composition. Preserve the method, variable roles, directionality, comparison structure, and qualitative phenomenon as precisely as the evidence supports. Synthetic values and schematic geometry must remain visibly non-evidentiary. Use charts or diagrams when they communicate a particular aspect more effectively. Do not default to flowcharts, and do not add decorative visuals. Every additional visual must explain a distinct aspect of the topic.
8. Put private PNG or JPEG image bytes beneath `tmp/automatic-visuals/`, bind their exact SHA-256 in the package, and never use a source figure whose public reuse rights are unknown. For every generated image, bind `generation.source_reference` to the exact source ID, PDF hash, and page locator that informed the brief; set `generation.reproduction_policy` to `scientific-content-faithful_visual-form-original`; include the exact visible label `Conceptual illustration — not research evidence` in the image and prompt; and describe the synthetic or omitted elements under `limitations`. Generated media must not be presented as evidence. Order `artifacts` with the primary visual first.
9. If any evidence, locator, identity, relevance, scope, image provenance, or reuse right is uncertain, do not create a package. A no-update day is valid.

The transaction, not this prompt, decides whether the package is valid and publishable. Never edit an accepted object, overwrite a pulse, advance a checkpoint, or run Git directly.
