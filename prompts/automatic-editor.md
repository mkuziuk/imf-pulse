# Automatic literature editor

Prepare at most one automatic pulse package for today's hash-bound immutable external batch.

1. Do not rely on prior task conversations. Before fetching a PDF, run `scripts/build_editorial_context.py`, compare the entire bounded candidate batch with its sealed coverage index, and read the full `bound_pulse` bodies only for the prior pulses you judge most topically similar.
2. Select only a materially relevant arXiv primary paper with an exact candidate ID and SHA-256. Accepted source versions are filtered by the monitor and rejected again by the transaction; never fetch or package one.
3. Require semantic novelty over the accepted coverage. The candidate must add a distinct method, theorem or result, experiment, contradiction, or open question—not merely a new metadata record, source version label, application domain, or paraphrase of an accepted pulse. If it does not, return no update.
4. Fetch only the official arXiv PDF with `scripts/fetch_arxiv_evidence.py`. Never fetch code, supplementary archives, Sci-Hub, or an untrusted redirect.
5. Inspect the PDF statically with the PDF skill. Do not execute embedded actions or source code. Record exact page locators and distinguish what the paper states from interpretation.
6. Create one private `data/automatic/packages/YYYY-MM-DD.json` conforming to `schemas/automatic-pulse-package.schema.json`. Bind the exact batch, candidate, candidate hash, PDF hash, page extracts, append-only knowledge objects, artifacts, and pulse prose. Author only editorial and interpretive content. The validator derives immutable source identity from the bound candidate in code: title, authors, publication date, canonical URL/location, versioned source ID/path, classification, and reviewed rights boundary. Legacy schema fields may still be present in a package, but they are not model authority and are replaced before semantic validation. Do not expand initials, normalize spelling, or substitute cleaner PDF metadata in evidence labels; human-readable names may be used in `rights.creator` and pulse prose.
7. Before invoking the guarded wrapper, run `.venv/bin/python scripts/validate_automatic_package.py --project-root "$PROJECT_ROOT" --date "$DATE"`. If it returns `failed`, read the exact error, compare the package with the bound candidate or PDF, repair only private package or visual staging, and run the read-only validator again. Make at most three repair attempts, and only for mechanical errors whose exact correction is present in the bound inputs. Never edit the immutable batch, candidate hash, PDF, accepted knowledge, or validation code. If the package still fails or the error exposes genuine evidence, identity, rights, or scope uncertainty, preserve it by moving it to a new non-overwriting path beneath `data/automatic/rejected/`, leave no package at the deterministic dated package path, and proceed with the wrapper as a no-package run. Do not force a package through.
8. State the robustness definition and target explicitly. Do not transfer linear-filter results to adaptive or robust recursion. Absence of an experiment is a limitation, not evidence of failure.
9. Write for a technically curious reader who has not read the paper and may not know the niche. Introduce the object and central question in plain language. When a specialized term first becomes necessary, prefer a short plain-language gloss before or beside the formal term, and expand every acronym on first use. Apply the same pattern to the opening of each Signal section. Keep formal terminology where it carries precision, and never simplify away assumptions, scope, uncertainty, or limitations.
10. Select one or more explanatory visuals that help a newcomer understand the object, phenomenon, dataset, or experimental setting. Prefer a relevant primary-source figure only when its public reuse rights are explicitly cleared. When rights are incompatible, create a scientific-content-faithful visual surrogate instead: inspect the exact PDF page and caption, identify the scientific entities and qualitative relationships that matter, and express those semantics in an original editorial composition. Preserve the method, variable roles, directionality, comparison structure, and qualitative phenomenon as precisely as the evidence supports. Synthetic values and schematic geometry must remain visibly non-evidentiary. Use charts or diagrams when they communicate a particular aspect more effectively. Do not default to flowcharts, and do not add decorative visuals. Every additional visual must explain a distinct aspect of the topic.
11. Put private PNG or JPEG image bytes beneath `tmp/automatic-visuals/`, bind their exact SHA-256 in the package, and never use a source figure whose public reuse rights are unknown. For every generated image, bind `generation.source_reference` to the exact source ID, PDF hash, and page locator that informed the brief; set `generation.reproduction_policy` to `scientific-content-faithful_visual-form-original`; include the exact visible label `Conceptual illustration — not research evidence` in the image and prompt; and describe the synthetic or omitted elements under `limitations`. Generated media must not be presented as evidence. Order `artifacts` with the primary visual first.
12. If no candidate survives the bounded scan, or any evidence, locator, identity, relevance, semantic novelty, scope, image provenance, or reuse right is uncertain, do not create a package. A no-update day is valid; do not fall back to an accepted source.

The resumable scheduled driver, not this prompt, decides whether the package is valid and publishable. Never edit an accepted object, overwrite a pulse, advance a checkpoint, or run Git directly.
